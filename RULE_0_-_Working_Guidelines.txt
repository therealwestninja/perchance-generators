# Working Guidelines 
1. Chat log: every session appends to `src/CHAT_LOG.md` (date, requests, decisions, what was built/verified). Re-orient from it after clearing chat, plus `src/README.md`, `src/SPEC.md`, `src/TODO.md`, `src/MEMORY_CUBE.md`.
2. Issues log: every fix gets an entry in `src/ISSUES_FIXES.md` (symptom, cause, fix, what to watch when touching that area again). Check it before fixing anything nearby.
3. Code reference: `src/CODE_REFERENCE.md` maps every system, its hooks, and the generator's objective. Update it when systems gain/lose hooks.
4. Request flow: research first, ask clarifying questions, suggest options, draft a best-practices plan with research shown, present plan + research + best practices, wait for approval, then build.
5. Testing harness: `src/tests/` holds runnable suites (via `page_eval` with `path`). All suites must run green before reporting done. Suites force offline deterministic mode where AI is involved. Slots 8 and 9 are reserved for tests — never player saves. Suites back up the live session to slot 9 and restore it.
6. Pause protocol: on any issue or unexpected result, stop, notify the user with what happened, research solutions, present plan changes, wait for approval.
7. Efficacy + cohesion: after every feature or system is added or changed, test it and every system it works in tandem with — run the harness green plus a live pass of the touched flows before reporting done.
8. Change log: every change gets a dated entry at the bottom of `src/change.log` (what, why, what verified).
9. Prove the wire: "no error" is not success. After wiring code to a boundary (DOM node, plugin, save data, pjs value), verify the real result — element exists and updated (`querySelector` non-null), save actually mutated, output text changed. Read console + `perchanceErrors` output as primary evidence. Confirm async plugin methods exist before calling; poll where needed. When behavior is wrong, bisect by disabling one binding/call at a time.
10. Reverse-treeshake audit: after heavy generated/refactored bursts, inherited drift, or before high-stakes gates — single pass, one bounded scope in `src/treeshake-worklist.md`, producer+consumer read side-by-side, contract diffed by eye (names, shapes, units, IDs, nullability), one concrete failing scenario per finding or no finding, fix at the seam, lock the shape in a test, mark rows DONE/CLEAN/DEFERRED. Null-controls required: prove off-means-unchanged and neutral-input-stays-neutral as hard test assertions.
11. Boundaries: explicit consent before destructive edits, user-visible wording changes, or ambiguous architecture calls. Filename map to AIH guidelines: chat.log→`src/CHAT_LOG.md`, issues_fixes.log→`src/ISSUES_FIXES.md`, architecture_reference.md→`src/CODE_REFERENCE.md`, change.log→`src/change.log`, handoff-note→`src/TODO.md`, worklist→`src/treeshake-worklist.md`, memory-cube→`src/MEMORY_CUBE.md`.
12. Memory cube (faceted recall): `src/MEMORY_CUBE.md` is the keyed recall layer over the chronological logs (indexes them, never replaces them). One point per line: keys + kind (decision|fix|gotcha|wire|spec|pref) + date + status + one-line summary + pointer to the full record. RECALL FIRST before touching a system or fixing anything: (a) skip points with status `superseded→[id]`/`done`/out-of-scope (hard predicate — keyword overlap never overrides it); (b) keep points whose keys overlap the context; (c) prefer `decision`/`gotcha`/`wire` and freshest date — then CITE what you recalled. APPEND after learning something durable. SUPERSEDE, never delete.
